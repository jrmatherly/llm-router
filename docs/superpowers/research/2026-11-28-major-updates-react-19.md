## The 14 typecheck errors, grouped by cause (run)

**Cause A: bare `useRef<T>()`. 6 x TS2554.** React 19 types require an argument for `useRef`.

- `packages/ui/src/pages/home/App.tsx:733` `useRef<number>()` (autoSaveTimer)
- `packages/ui/src/pages/home/App.tsx:734` `useRef<string>()` (explicitSaveKey)
- `packages/ui/src/pages/home/App.tsx:746` `useRef<number>()` (toastTimer)
- `packages/ui/src/pages/home/components/network-logs.tsx:1608` `useRef<Worker>()`
- `packages/ui/src/pages/home/components/profiles.tsx:422` `useRef<number>()`
- `packages/ui/src/pages/home/shared/controls.tsx:359` `useRef<number>()`

**Cause A, knock-on: 7 x TS2322.** This is the "something else" behind 14 versus 7. Once the zero-argument overload is gone, TypeScript types those refs as `RefObject<T>` with `T` excluding `undefined`, so every `ref.current = undefined` fails. They disappear with the Cause A fix, with no edit of their own (run).

- `App.tsx:889`, `App.tsx:908`, `App.tsx:947`, `App.tsx:1063` (number refs)
- `App.tsx:1111` (string ref)
- `network-logs.tsx:1622`, `network-logs.tsx:1697` (Worker ref)

**Cause B: global `JSX` namespace removed. 1 x TS2503.**

- `packages/ui/src/pages/home/components/update.tsx:175` return type `icon: JSX.Element`.

## The failing UI test (run, read)

`packages/ui/test/component/components.test.tsx:180`, test "form primitives preserve native semantics, state, and caller styling". It asserts `/readonly=""/` on `renderToStaticMarkup(<Input readOnly />)`.

- React 18 output: `readonly=""`. React 19 output: `readOnly=""`.
- Why (read): React 19's server renderer (`react-dom/cjs/react-dom-server.node.production.js` near line 980) handles `readOnly` in its boolean-attribute case and pushes the prop `name` as written. React 18 mapped it to the lowercase attribute name.
- HTML attribute names are case-insensitive, so the parsed DOM is the same. The test change is legitimate: make the match case-insensitive.

## Behaviour the tests cannot see

- **Ref callbacks returning a value.** None. No inline `ref={(...) => ...}` in `packages/ui/src` or `docs/src`; every `ref=` passes a ref object or a forwarded `ref` (read, grep). Unchanged.
- **forwardRef.** 26 uses, all in `components/ui/*` (tabs, card, popover, label, tooltip, switch, dialog, input, button and more). React 19 still supports `forwardRef`; `ref` as a plain prop is new but optional. No code reads `element.ref` or `props.ref` (read, grep). Unchanged. Moving off `forwardRef` is optional follow-up, not part of the upgrade.
- **Portals.** `popover.tsx:31` and `tooltip.tsx:31` call `createPortal(..., document.body)` behind a `typeof document === "undefined"` guard. `createPortal` is unchanged in 19 (read). `PopoverPortal` defaults `open = true`, so on SSR it renders nothing and the client renders the portal; same under 18, and the docs pages log no hydration errors (run). Unchanged.
- **motion 14.** Version identical before and after (14.14.0) and it declares React 19 support. `AnimatePresence` is used in `api-keys.tsx`, `dashboard.tsx` (one with `mode="wait"`), `dialog-stack.tsx`, `extensions.tsx`, `shared/controls.tsx`; `LayoutGroup` and `layout` in `shared/external.tsx` and `api-keys.tsx:168` (read). The docs demos animate after clicks (run), but exit and layout animations in the desktop app were not observed. Expected unchanged (inferred).
- **createRoot entry points.** `pages/home/main.tsx:11`, `pages/tray/main.tsx:9`, `pages/browser/main.tsx:356` all use `createRoot(...).render(...)` from `react-dom/client`, with no options (read). No `ReactDOM.render`, `hydrateRoot`, `unmountComponentAtNode` or `findDOMNode` anywhere (read). Unchanged; the removed APIs were never used.
- **StrictMode.** Only `pages/home/main.tsx:12`. React 19's StrictMode changes: ref callbacks run twice on mount (none exist here), and `useMemo`/`useState` initialisers reuse the first result on the double render. StrictMode does nothing in production builds. No change here (inferred from the read).
- **Errors to `window.reportError`.** React 19 sends uncaught render errors to `window.reportError` instead of re-throwing, and caught ones to `console.error`. The UI has no error boundary, no `onUncaughtError`/`onCaughtError`/`onRecoverableError` root option, and no `window.onerror` or `error` listener (read, grep). An uncaught render error still unmounts the root, as in 18; the console shows one report instead of 18's duplicate logging (inferred). Not checked: whether the Electron main process captures renderer console errors, which would see a different message count.
- **Other removed APIs.** No `defaultProps` on function components, `propTypes`, `contextTypes`, string refs, `react-dom/test-utils`, `react-test-renderer` or `useFormState` (read, grep; the `ref="` hits were `href="` in SVGs).
