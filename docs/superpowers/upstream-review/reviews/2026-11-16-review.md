# Upstream review - 2026-11-16

Window: `057abaa1..da96d5dfb4d3d7f91818043a1500c4a447f3cdcf` (release v3.1.5), 50 commits (21 merges, 29 to classify). Driver: `--stat`, `--port-check` on all 29, `--dry-run-merge` (61 conflicting files), `--github` (status diverged, ahead_by 218, behind_by 50).

This is the first review. It covers everything upstream did between the fork point and v3.1.5. Three reviewers read every diff in full, one per area. The lead then re-read the fork code behind the seven highest-value claims; those rows say "lead-checked". Nobody ran a port or a test, so every "applies" below comes from `--port-check` and every behavior claim comes from reading code unless a row says "measured".

Commit links: `https://github.com/musistudio/claude-code-router/commit/<sha>`.

## Headline

Upstream spent the window on real defects, and most of them exist in the fork today. Twenty-one fixes are worth porting. Four of them close a leak or a data-loss path the fork's own audit did not find: client cookies and Cloudflare headers reach providers, a truncated stream ends with a bare EOF, the request-log backfill reads every stored body into memory, and stdio MCP servers default to a framing the MCP standard does not use. Nothing upstream did argues for keeping the `x-llmr-route-fallback` header: no commit in the window reads it.

Three items need the owner's decision before any port: whether a port may write `~/.claude.json` (60796a97), whether the release build should carry patches to the third-party gateway source (704eec46 #1917, 086fd961 #1932), and the Codex desktop identity change (3c75352c with 704eec46), which changes which ChatGPT login a profile uses.

## Red flags

- **Provider header boundary.** Row 1 is a live leak. It was not in the 2026-11-16 audit.
- **Third-party source patches in the release build** (row 29). Upstream now ships a gateway that differs from the published package by about 1,900 patched lines.
- **Codex identity** (row 27). Upstream changed which ChatGPT account a managed profile acts as. The fork's current default shares the personal login.
- **`x-llmr-route-fallback`.** No commit in the window reads it, upstream's decoder has no caller at v3.1.5, and upstream pins the same gateway version. It can be removed.
- **Rotation.** Upstream did not fix the refresh-token rotation defect (F-C12). One upstream doc sentence says a copied login's refresh token is invalidated when the owner refreshes, which suggests the endpoint rotates. Not verified.
